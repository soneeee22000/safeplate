SafePlate

A customer asks in a language you don't speak whether the dish contains nuts. You have thirty seconds, a jar with a label in Polish, and a legal obligation not to guess. SafePlate is an agent that works the problem the way a careful chef would — and stops when it can't be sure.

Track 2 · Autonomous Agents $750 cash + $1,000 SerpApi credits Rita · Afaq · Yan · Pyae

The one thing this track is actually judging

Track 2 asks for an agent that “should do more than generate text: it should take useful, observable actions.” The organisers' own framing of the track is blunter — does it survive contact with failure? — and their stated instinct is that a linear prompt chain with no branching and no recovery caps out low.

So we are not building a happy path and hoping nobody pokes it. We are demoing the failure first. Every other team will show their agent succeeding. We show ours hitting a wall, recognising it, routing around it, and refusing when the evidence doesn't support an answer.

The agent trace — this is the demo

Gemma 4 decides which tool to call next based on what came back. Nothing below is a fixed sequence.

1
read_label(photo)
Gemma 4 vision + local OCR. Returns the ingredient text and a confidence.
2
read_label → low confidence, glare on the panel
The agent does not proceed on a bad read. It asks the server to re-shoot the label at an angle.
Recovery · retry with feedback
3
match_allergens(ingredients)
Deterministic lookup against the EU's 14 declarable allergens and their synonyms. Casein → milk. Semolina → gluten. No model judgement here, by design.
4
"natural flavourings" — unresolvable from the label
The agent recognises the gap and changes plan: lookup_product(brand, name) via SerpApi to find the manufacturer's published declaration.
Branch · external tool
5
Sources disagree · escalate(reason)
The retailer page lists no nuts; the manufacturer PDF says “may contain traces”. SafePlate does not average them.
Refuse · do not serve
6
issue_card(verdict, evidence, language)
Produces a printable safety card in the customer's language, with every source cited and the unresolved conflict named — and logs the decision.
Observable action

Six steps, four decision points, two recoveries, one refusal. That is the answer to “does it survive contact with failure?” — and it is visible on screen rather than asserted in the writeup.

The architecture argument: what the model does, and what it never does

Gemma 4 owns
Reading · translating · planning · deciding the next tool

Native function calling drives the loop. Multimodal reading of a photographed label. Multilingual output for staff and customer.

A lookup table owns
Whether an ingredient is a declarable allergen

The EU's 14 allergens plus synonyms, as data. A language model must never be the thing that decides whether casein is dairy.

This split is the strongest thing we can say to a judge who asks about hallucination. The reasoning is learned; the safety call is deterministic and auditable. Gemma is unambiguously core — it plans, reads and speaks — but it is never the last line of defence.

🔴 Gate this before anyone builds the loop

Two checks, twenty minutes, right now.

1. Can E2B read a real ingredient panel? We already know its vision fails on dense printed text — that finding is why Tesseract is installed. Photograph two real jars. If the model struggles, OCR feeds it instead, and the tool boundary doesn't change.

2. Does E2B actually emit well-formed tool calls? The entire agent depends on it. Test one round-trip with two tools before building four. If function calling is unreliable at 2B, fall back to a constrained JSON schema with a repair-and-retry step — which is itself a recovery behaviour the track rewards.

3. Re-time the loop. 4.1 s per call was measured on different prompts. A six-step agent run is six-plus inferences — measure the real thing before quoting any number in the pitch, and quote whatever the recording shows.

What I'd want argued with me

  • Why not the gym / pilates form coach? It's a structural mismatch for this track, not a weaker idea. Form checking is perception plus feedback — temporal pose estimation, which is MediaPipe's job, not a language model's. Track 2 wants planning, tool use and observable actions, and a form coach has none of the three. A live video demo is also a lighting-and-latency gamble on stage.
  • Are we giving medical advice? No, and the framing must hold under questioning: SafePlate guides staff through a check and cites its sources. It never declares food safe. Its most valuable output is “do not serve, I can't confirm.”
  • Track 2 pays less cash than Track 3 — $750 versus $1,000, though it adds $1,000 in SerpApi credits. Worth knowing; not worth reopening.
  • SerpApi credits aren't guaranteed. The starter pool is request-based and explicitly not a prize. Ask now, and cache fixtures so the demo runs regardless.
